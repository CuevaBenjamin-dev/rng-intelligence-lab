# Instrucciones para agentes de desarrollo

1. Lee `PROJECT_MEMORY.md` antes de iniciar cualquier tarea. Verifica el estado actual de Git y los archivos relevantes.
2. Trabaja sobre una tarea delimitada; respeta el alcance autorizado. Por defecto, solo datos sintéticos y ejecución local. No conectes a sistemas reales, automatices interacciones con participantes ni recopiles datos reales sin aprobación explícita y alcance documentado.
3. No inventes datos, hallazgos, métricas, autorizaciones o resultados de pruebas. Distingue hipótesis, hechos reportados y evidencia comprobada.
4. Respeta la separación cronológica de entrenamiento, validación y prueba. No uses información posterior al evento ni optimices sobre la prueba final.
5. Prefiere implementaciones simples, reproducibles y verificables. No agregues dependencias, servicios, infraestructura ni modelos complejos sin justificar la necesidad.
6. Ejecuta pruebas relevantes y registra el resultado real. Si no puedes ejecutar una prueba, indícalo.
7. Actualiza `PROJECT_MEMORY.md` cuando haya cambios relevantes: estado, decisiones, evidencia, bloqueos, tareas y próximo paso. Si el trabajo solo es una propuesta, márcalo como tal. Mantén el historial y no inventes hashes de commits.
8. No guardes credenciales, datos personales o datasets del cliente en el repositorio. No cambies visibilidad, publiques datos ni despliegues sin autorización explícita.
9. Presenta el resumen de cambios y las pruebas para revisión humana antes de confirmar o subir cambios, salvo que se te haya pedido expresamente hacerlo.
10. Documentación en español; identificadores de código en inglés. Mantén las pruebas junto con cambios funcionales.
